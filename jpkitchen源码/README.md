# 今天吃什么 · 日本版

> 住在日本的中文厨房助手。一键出今天三餐，把冰箱吃干净，买菜清单自带日语。

零后端、零账号、零依赖。所有数据只存在你自己浏览器的 localStorage 里，不上传任何地方。
构建产物是**一个 HTML 文件**，扔到任何静态托管上就能用。

---

## 它能干什么

| | |
|---|---|
| 🎲 **一键排今天** | 一个按钮出早/午/晚三餐。优先用冰箱里快过期的食材，优先你常做的菜，自动避开最近三天吃过的 |
| 🍖 **晚餐必有主菜** | 算法强制每顿正餐先锁一道有肉蛋奶鱼豆的主菜，不会给你排出「拌黄瓜 + 菠菜汤」这种 |
| 📊 **营养环** | 按身高体重算 TDEE，实时显示今天吃了多少 kcal、蛋白脂肪碳水各占目标多少 |
| 🧊 **冰箱** | 每样食材记购入日期算保质期，快过期的顶到最上面并优先推荐；做完菜自动扣库存 |
| 🛒 **买菜清单** | 自动带日语货架名，按「普通超市 / 中华食材店」分组；可复制 prompt 让 AI 排买菜路线 |
| 🍱 **周末备菜** | 挑几道适合提前做的菜，生成方案并**自动排进接下来几天的晚饭**，到那天打开自动填好 |
| 🍜 **外食** | 55 家日本连锁的点单建议，带中日菜名、价格、营养、以及「怎么点才不至于营养失衡」和一句点单日语 |
| 📷 **小票入库** | 复制指令 → 贴给任意 AI + 小票照片 → 结果粘回来，一键入库 |

## 怎么改

```bash
node build.js       # 没有任何依赖，装了 Node 就能跑
```

构建脚本**自带数据校验**，下面这些情况会直接中止并告诉你哪道菜有问题：

- 菜谱 id 重复、缺日语名、没有食材
- 食材没在 `ingredients.json` 里登记（那样买菜清单就出不了日语名）
- 三大营养素换算和 kcal 对不上超过 15%
- 标签不在白名单里、没有菜系标签
- `prepType` / `dinner` / `type` 字段不合法

改完 `git push`，Netlify 会自己跑 `node build.js` 并上线。

### 加一道菜

在 `data/recipes.json` 里加一个对象。字段说明见 [`docs/数据格式.md`](docs/数据格式.md)。
用到新食材的话记得同时在 `data/ingredients.json` 里登记它的日语名。

也可以直接在 App 里加：菜谱页右上角 ＋，或者复制 prompt 让 AI 生成 JSON 粘回来（那样只存在你自己手机里，不进仓库）。

## 部署

**Netlify**（当前用的）：仓库连上去，构建命令和发布目录已经写在 `netlify.toml` 里，不用手填。

**任何其他静态托管**：把 `dist/index.html` 拖过去就完事。

> ⚠️ 直接用 `file://` 双击打开的话，部分浏览器会禁用 localStorage，数据存不住。
> 本地测试请起个 server：`npx serve dist` 或 `python3 -m http.server -d dist`

## 技术备注

- 无框架、无构建工具链、无 npm 依赖。`build.js` 只用 Node 内置模块
- 渲染是朴素的 `innerHTML =` 全量重刷 + 事件委托
- 状态是单个对象 `S`，序列化进 `localStorage['jpKitchen_v3']`
- 菜谱数据存在常量里不进 localStorage，所以更新版本不会覆盖你自己加的菜和收藏
- 深色模式跟随系统；内嵌 manifest 和图标，可「添加到主屏幕」当 App 用
- 数据可在设置里导出 / 导入备份
