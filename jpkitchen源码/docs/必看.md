# 数据格式说明

改内容基本只需要动 `data/` 下这四个文件。改完跑 `node build.js`，它会校验并告诉你哪里不对。

---

## `data/recipes.json` — 菜谱

```json
{
  "id": "jp01",
  "name": "姜烧猪肉",
  "ja": "豚の生姜焼き",
  "en": "Ginger Pork",
  "emoji": "🐖",
  "type": "meal",
  "tags": "猪,日料,快手菜",
  "spicy": "gentle",
  "cal": "light",
  "keep": false,
  "fav": true,
  "dinner": true,
  "serving": 1,
  "prepType": "marinate",
  "prep": "肉加酱汁提前一晚腌好冷藏，当天下锅 6 分钟",
  "ings": ["猪肉片", "生姜", "洋葱", "酱油", "味醂", "料酒"],
  "nutri": { "kcal": 420, "p": 28, "f": 24, "c": 14 },
  "steps": "猪肉片用酱油味醂料酒姜泥腌10分钟|洋葱切丝|热油下洋葱炒软|下肉片大火炒到变色|倒入腌料收汁",
  "note": "日本家庭最常做的一道，配白饭一绝"
}
```

| 字段 | 说明 |
|---|---|
| `id` | 唯一，不能重复。自己加的建议用 `my01` 之类的前缀避免撞车 |
| `name` / `ja` / `en` | 中文名 / 日语名（日本超市和餐厅的通行叫法）/ 英文名 |
| `emoji` | 一个 emoji，显示在卡片左边 |
| `type` | `meal`（正餐）或 `breakfast`（早餐） |
| `tags` | 逗号分隔，**必须从下面的白名单里选**，且**至少含一个菜系标签** |
| `spicy` | `spicy` 辣 / `gentle` 不辣。开「肠胃弱」模式会滤掉辣的 |
| `cal` | `light`（≤450 kcal）/ `high`（>450）。**必须和 `nutri.kcal` 一致**，构建时会校验 |
| `keep` | 做一次能吃两顿 → `true`。会显示 🍱 徽章，备菜排期时排两天 |
| `fav` | 常做菜 → `true`。「⭐ 只用常做菜」模式只用这些，一键排菜也会加权 |
| `dinner` | **能当晚餐主菜** → `true`。有肉蛋奶鱼豆制品、蛋白质撑得住的才填 true |
| `serving` | `nutri` 对应几人份，统一填 `1` |
| `prepType` | 备菜方式，见下表 |
| `prep` | 一句话备菜提示，**要写清能放多久** |
| `ings` | 食材中文名数组，**只写名字不写用量**。每一样都必须在 `ingredients.json` 里登记 |
| `nutri` | 一人份的 `{kcal, p, f, c}`。要求 `p*4 + f*9 + c*4` 在 `kcal` 的 ±15% 内 |
| `steps` | 用 `|` 分隔的步骤，每步一句话，写清火候和时间 |
| `note` | 一句话小贴士 |

### 标签白名单

```
鸡  猪  牛羊  海鲜  蛋  豆制品  素菜  汤  炒菜  炖菜  凉菜  烤箱
汁物  丼物  面食  米饭  快手菜  聚会菜  下酒菜  便当菜  熟食
中餐  日料  西餐  韩餐  东南亚  意餐          ← 菜系，至少要有一个
```

### `prepType` 四选一

| 值 | 含义 | 典型 |
|---|---|---|
| `batch` | 整锅做好分装存，吃时只要复热 | 炖菜、咖喱、肉酱、卤味、汤 |
| `marinate` | 主料提前腌好，当天只要下锅 | 照烧鸡腿、姜烧猪肉、烤鸡翅、牛排 |
| `cut` | 提前洗切分装，当天热锅就炒 | 各种炒菜 |
| `fresh` | 现做最好，别提前 | 凉拌、煎鱼、蒸蛋、面类 |

`batch` 和 `marinate` 的菜会进「周末备菜」的候选池。

## `data/ingredients.json` — 中日食材对照

```json
{
  "猪肉片": {
    "ja": "豚こま切れ肉",
    "store": "normal",
    "en": "pork slices",
    "cat": "🥩 肉蛋海鲜",
    "shelf": 3
  }
}
```

| 字段 | 说明 |
|---|---|
| `ja` | **日本超市货架上的实际叫法**，不是直译。生抽→醤油、淀粉→片栗粉、大葱→長ねぎ |
| `store` | `normal`（普通超市有）/ `chinese`（要去中华食材店、業務スーパー、カルディ）。买菜清单据此分组 |
| `en` | 英文名，选填 |
| `cat` | 分类，**必须**是下面十一个之一 |
| `shelf` | 买回来放冰箱能放几天。**≤ 2 天时会触发「该吃了」提醒**；≥180 视为常备不参与临期计算 |

### 分类白名单

```
🥬 蔬菜    🍎 水果    🥩 肉蛋海鲜   🍚 主食干货   🧂 调料酱汁   🌿 香料香草
🥛 乳品甜点  🍳 早餐常备  🏪 现成即食   ☕ 茶饮     🧴 日用品
```

> `🧂 调料酱汁` 和 `🌿 香料香草` 这两类被视为「调料」：不计入「冰箱里有没有」的判定，做完菜也不扣库存。

保质期参考：叶菜 4 / 根茎菜 14 / 菌菇 5 / 水果 7 / 生鲜肉 3 / 生鲜鱼 2 / 鸡蛋 21 / 豆腐 5 / 牛奶 7 / 面包 4 / 米面干货 365 / 调料 365 / 冷冻品 90 / 罐头 365

## `data/eatout.json` — 外食建议

```json
{
  "id": "eo01",
  "shop": "吉野家",
  "shopJa": "吉野家",
  "genre": "牛丼",
  "name": "牛肉盖饭 中碗 + 生菜沙拉 + 半熟蛋",
  "nameJa": "牛丼 並盛、生野菜サラダ、半熟玉子",
  "emoji": "🍚",
  "price": 708,
  "nutri": { "kcal": 745, "p": 27, "f": 25, "c": 98 },
  "healthy": true,
  "tip": "光吃牛丼碳水爆炸、蛋白质不够。加一份「サラダ」和「半熟卵」，¥200 出头就能把蛋白质拉到 30g",
  "order": "牛丼 並盛、サラダ、半熟卵",
  "jp": "「牛丼の並と、サラダと半熟卵をお願いします」"
}
```

| 字段 | 说明 |
|---|---|
| `shop` / `shopJa` | 店名的中文叫法 / 招牌上的日文原名 |
| `genre` | 品类，见下面的白名单 |
| `name` / `nameJa` | 点什么，中文 / 日文菜单原写法 |
| `price` | 日元整数 |
| `nutri` | 这一份的营养，同样要求换算自洽 |
| `healthy` | 蛋白 ≥25g 且 kcal ≤750 → `true`。有专门的「💪 高蛋白」筛选 |
| `tip` | **最重要**。怎么点才不至于营养失衡 / 怎么加蛋白质 / 什么时段便宜 |
| `order` | 完整点单内容，日文 |
| `jp` | 一句能直接念给店员听的日语，带「」。点一下可复制 |

### 品类白名单

```
牛丼  定食  寿司  拉面  荞麦面  乌冬面  居酒屋  烤肉  咖喱  意大利
家庭餐厅  中华  汉堡  便利店  天妇罗  鳗鱼  韩餐  泰餐  咖啡轻食  自助沙拉
```

> 这里**只放堂食**。日本外卖又贵又慢，不收录任何外卖 / デリバリー内容。

## `data/drinks.json` — 饮品甜点

比菜谱简单，字段：`id / name / ja / en / emoji / cat / ings / note`。
`cat` 是 `coffee` / `tea` / `mocktail` / `dessert` 之一。

---

## 让 AI 帮你加菜

`data/` 里的格式就是标准。想批量加菜的话，把这份文档连同要加的菜名一起丢给 AI，让它按格式输出 JSON 数组，粘进 `recipes.json` 再跑 `node build.js` 校验。

App 内也内置了单道菜的生成 prompt（菜谱页 ＋ → 底部「懒得填？让 AI 填」），不过那样加的菜只存在你手机的 localStorage 里，不会进仓库。
